# 迭代计划

> 0.1.1 是基线（完整跑通 MTP 文件管理的基本能力）。之后每完成下面一项就发一个修订版（0.1.2、0.1.3…），
> 规则见 [RELEASE.md](RELEASE.md)。顺序按优先级排列，可以随时调整；版本号只是预估，以实际发布为准。
> 功能范围以 [SCOPE.md](SCOPE.md) 为准，技术背景见 [../CONTEXT.md](../CONTEXT.md)。

## 近期：把 0.1.1 补扎实

| 预计版本 | 内容 | 完成标准 |
|---|---|---|
| 0.1.2 | **补实机验证**：⌘C 后在 Finder 里 ⌘V、拖到 Finder 下载（含 Finder 里的进度显示）、图片缩略图、图标视图里拖动、设备事件（DBI 是否会发对象增删事件）。发现问题当场修。如果 Finder 不接受粘贴文件承诺，按 SCOPE 的备选方案改：小文件先下载到缓存再放文件 URL，大文件提示改用拖放。 | 每一项都有实机结论写进 CONTEXT.md |
| 0.1.3 | **DBI 移动后的列表纠正在重启后仍然有效**：把 MoveLedger 存到磁盘，按设备 + 路径名记录（句柄会变），设备重新连接后能判断是否还需要纠正。 | 移动 → 重启 Pier → 原文件夹不再显示已移走的文件 |
| 0.1.4 | **普通 Android 手机实测**：文件名、修改日期列、64 位大小、分段写（Android 的 SendObjectInfo 只声明首块大小这条假设）、PTP 事件、删除文件夹的行为；结果写进 DeviceQuirks。 | 至少一台 Android 手机上跑通上传、下载、改名、删除、移动 |
| 0.1.5 | **大目录体验**：先显示条目数量，优先补全可见行（滚动时调整优先级）；试用 GetObjectPropList 批量读取，代替逐个 GetObjectInfo。 | SD 卡里上千个文件的目录打开在 1 秒内出第一屏 |
| 0.1.6 | **DBI 安装超过 4 GB 的 NSP**（需要用户明确同意往安装存储写入，并准备文件）：验证分段写能不能装上；不能的话给出明确提示，说明替代方法。 | 有实机结论；界面提示与结论一致 |

## 之后：体验和稳定性

- 指令超时后的恢复再打磨：区分"设备忙"和"断开"，长时间无响应时界面给出明确状态。
- 传输窗口：除了 popover 之外再提供一个独立的传输窗口；下载完成后在 Dock 图标上提示。
- 剩余空间：DBI 上传或删除之后，按本地记账估算剩余空间（设备给的值不会更新）。
- 无障碍与键盘：VoiceOver 标签，全键盘操作路径检查。
- 本地化整理（目前只有简体中文）。

## v1.1 范围（来自 SCOPE.md，到这里时由用户决定是否升到 0.2.0）

- 插上设备自动弹出窗口（菜单栏常驻助手，类似 AFT Agent）。
- 跨设备拖拽（经本机中转）、设备内复制（先下载再上传）。
- App Sandbox 可行性评估。
